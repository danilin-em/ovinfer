# Дизайн: ovinfer v0.1 — пакет инференса на OpenVINO + OpenAI-совместимый сервер

Дата: 2026-06-07
Статус: **одобрена** — ревью пользователя пройдено 2026-06-07 (итоги: библиотечный
путь №2 и extras убраны из v0.1; добавлены device-map, preload и
embeddings-пайплайн). Следующий шаг — навык writing-plans, затем реализация

## Контекст и мотивация

ovinfer — самодостаточная платформа инференса на OpenVINO (openvino-genai).
Продукт v0.1 — **OpenAI-совместимый HTTP-сервер**: установить `ovinfer`, запустить
`ovinfer server` — приложения ходят по HTTP (openai-python, LibreChat, Continue и т.п.).

Библиотечный путь (`uv add ovinfer`, `from ovinfer import Backend` без HTTP) —
**вне v0.1**: для скрипта с одной моделью голый openvino-genai достаточен сам по
себе, а ценность ядра (кеш пайплайнов, локи, OpenAI-семантика) раскрывается именно
в серверном контексте. Внутренняя граница ядро/транспорт при этом сохраняется,
поэтому открыть публичный API позже — дёшево (экспорт + документация).

Проект выделен из `~/.openvino` (машинная обвязка Intel-стека: wrapper `openvino-env`,
vendored-драйверы). Это **два разных проекта**: ovinfer ничего не знает про обвязку и
работает на любой машине с исправным OpenVINO-окружением; на машинах, где нужен
vendored-стек, процессы ovinfer просто запускаются под `openvino-env`. История git
начата начисто; контракт API (`server.py`-каркас) и его дизайн-спека перенесены
файлами из `~/.openvino`.

Долгосрочное видение (вне v0.1): несколько моделей одновременно, management-API
загрузки/выгрузки моделей с выбором устройства, каталог источников моделей
(huggingface.co/OpenVINO, modelscope.cn/organization/OpenVINO) — самодостаточность
«от скачать до запустить».

## Скоуп v0.1

Каркас репозитория + порт ядра и контракта + **два реальных пайплайна**:
LLMPipeline (chat/completions, включая стриминг) и TextEmbeddingPipeline
(embeddings) + CLI `ovinfer server`. Мультимодельность с выбором устройства на
модель (`--device-map`) и прогревом на старте (`--preload`) — в скоупе.
Реальный инференс — проверка, что внутренняя граница ядро/транспорт проведена правильно.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Архитектура | **Sync-ядро + тонкий транспорт.** Ядро синхронное (блокирующее), plain-Python аргументы, FastAPI не импортирует — граница ради тестируемости и возможного библиотечного API в будущем. Async — только в транспорте: `def`-роуты FastAPI выполняются в threadpool автоматически. Async-first ядро отвергнуто (og.\* всё равно блокирующий). |
| Сервер | **Внутри пакета** (`ovinfer/server.py`), потому что запуск — подкоманда console-script: `ovinfer server --listen 127.0.0.1:8000`. |
| Зависимости | Единый набор, **без extras**: `openvino==2026.2.0`, `openvino-genai==2026.2.0`, `fastapi`, `uvicorn`, `python-multipart`. Продукт один (сервер) — делить зависимости не для кого. |
| Библиотечный путь | **Отложен (вне v0.1).** Публичный API не обещается; `Backend` — внутренний модуль, его интерфейс можно менять свободно. Для скриптов с одной моделью og достаточен напрямую; открыть API — когда появится реальный потребитель. |
| Готовый сервер (OVMS) | **Отвергнут (build, не buy).** OpenVINO Model Server даёт OpenAI-совместимые LLM-эндпоинты, но это тяжёлый C++-деплой со своей моделью развёртывания: плохо ложится на vendored-стек этой машины (`openvino-env`) и не покрывает все 11 og-пайплайнов контракта. Тонкий Python-сервер над og — меньше движущихся частей, полный контроль. |
| Хранилище моделей | Дефолт **XDG**: `$XDG_DATA_HOME/ovinfer/models` (обычно `~/.local/share/ovinfer/models`); переопределяется (например, на `~/.openvino/models`). |
| Конфиг | Приоритет: **CLI-аргументы > env (`OVINFER_*`) > дефолты.** |
| Device на модель | **`--device-map` / `OVINFER_DEVICE_MAP`** (`org/model=NPU,org/model2=GPU`); модели вне маппинга — на дефолтный `--device`/`OVINFER_DEVICE`. Device — свойство модели, не запроса: в OpenAI-протоколе устройства нет, клиент выбирает модель. Per-request device отвергнут. |
| Прогрев | **Лениво + `--preload` / `OVINFER_PRELOAD`** (список model_id). Пайплайны создаются при первом запросе; preload греет перечисленные модели на старте — NPU-компиляция занимает десятки секунд, холодный старт бьёт по первому клиенту. |
| Каталог моделей | **v0.2**: YAML-файл источников + `ovinfer models list/download` — отдельная подсистема, проектируется своей спекой. |

## Структура репозитория

```

  ovinfer/
    __init__.py       # версия пакета; публичного API в v0.1 нет
    config.py         # резолв настроек: XDG-дефолты, env OVINFER_*
    errors.py         # ModelNotFound, PipelineNotImplemented — доменные, без HTTP
    registry.py       # list_models(), resolve_model_dir() — принимают models_root
    backend.py        # Backend: LRU-кеш пайплайнов, chat()/chat_stream()/заглушки

    cli.py            # entry point `ovinfer`: подкоманда server
  docs/superpowers/specs/
  README.md
  server.py           # перенесённый каркас контракта; растворяется в пакет при
                      # реализации и удаляется
```

## Packaging (pyproject.toml)

- `[project]`: name `ovinfer`, requires-python `>=3.12`; зависимости — по таблице
  решений выше (без extras).
- `[project.scripts]`: `ovinfer = "ovinfer.cli:main"`.
- Конфиг через env использует префикс `OVINFER_` (не `OV_` — короткий префикс
  занят настройками самого OpenVINO): `OVINFER_MODELS_ROOT`, `OVINFER_DEVICE`
  (дефолт `CPU`), `OVINFER_DEVICE_MAP` (`org/model=NPU,...`), `OVINFER_PRELOAD`
  (список model_id через запятую), `OVINFER_MAX_PIPELINES`,
  `OVINFER_USE_CONTINUOUS_BATCHING`.

Установка:

- `uv tool install <локальный-путь-или-GitHub-URL>` → `ovinfer server --listen 127.0.0.1:8000`.
- Для разработки: `uv sync` в репозитории, `uv run ovinfer server`.

## CLI (`ovinfer/cli.py`)

## Ядро (`backend.py`) — внутренний интерфейс

Потребитель интерфейса — транспорт (и тесты); стабильность наружу не обещается.
Описан подробно, потому что это главная граница дизайна.

```python
from ovinfer.backend import Backend
from ovinfer.errors import ModelNotFound, PipelineNotImplemented

backend = Backend()   # дефолты из config; или Backend(
                      #   default_device="GPU",
                      #   device_map={"OpenVINO/gemma-3-4b-it-int4-cw-ov": "NPU"},
                      #   preload=[...], models_root=..., max_pipelines=...)

backend.list_models()                    # -> list[str], "org/model"

result = backend.chat(
    "OpenVINO/Qwen3-0.6B-int4-ov",
    [{"role": "user", "content": "..."}],
    temperature=0.7, top_p=0.9, max_tokens=512,
)
# result: ChatResult(text, finish_reason, prompt_tokens, completion_tokens)

for delta in backend.chat_stream(model_id, messages, max_tokens=512):
    ...   # str-дельты; finish_reason — return value генератора (StopIteration.value)

result = backend.embed(
    "OpenVINO/Qwen3-Embedding-0.6B-int8-ov",
    ["query one", "query two"],
)   # -> EmbedResult(vectors, prompt_tokens); векторы в порядке входа
```

- **`messages` — list[dict]** `{"role", "content"}` (content: строка или список
  частей) — «родной» формат chat-template'ов, не изобретение OpenAI; уместен в ядре.
- **`ChatResult`** — frozen dataclass; транспорт собирает из него OpenAI-тело.
- **Протокол стрима**: генератор yield'ит `str`-дельты, `finish_reason` возвращает
  как return value (PEP 380, `StopIteration.value`). Простой случай остаётся простым
  (`for delta in ...`), транспорту доступен «length vs stop».
- **VLM-диспетчеризация** (`messages_have_images`) — в ядре: доменная логика.
- **Ошибки доменные**: `ModelNotFound`, `PipelineNotImplemented` без HTTP-кодов;
  маппинг на статусы и формат OpenAI — в транспорте.
- **Остальные методы** (`rerank`, `image_generate`, `image_edit`,
  `transcribe`, `translate`, `speech`, `video_generate`) сохраняются с
  plain-сигнатурами и бросают `PipelineNotImplemented` — контракт 501 из
  перенесённой спеки не меняется.

## Реестр моделей и конфиг

- `registry.list_models(models_root)` / `resolve_model_dir(models_root, model_id)` —
  как в перенесённом каркасе (скан `org/model` на два уровня, критерий — `*.xml`,
  membership-check блокирует path traversal), но без глобальных переменных.
- `config.py` резолвит: явный аргумент > `OVINFER_*` env > XDG-дефолт.
  `$XDG_DATA_HOME` пустой/не задан → `~/.local/share`.

## Кеш пайплайнов и конкурентность

- LRU-кеш `{(model_id, kind) → (pipeline, lock)}`, лимит `max_pipelines`
  (дефолт **2**). При переполнении выгружается давно не использованный: запись
  удаляется из кеша; объект освобождается GC, когда последний работающий поток его
  отпустит (занятый пайплайн нельзя выдернуть из-под потока).
- Два уровня локов:
  - глобальный `threading.Lock` — операции с кешем (lookup/insert/evict);
  - per-pipeline `threading.Lock` — создание и генерация: og-пайплайны не
    потокобезопасны, запросы к одной модели сериализуются; к разным — параллельны.
- Создание пайплайна (секунды) — под per-pipeline-локом, **вне** глобального:
  медленная загрузка одной модели не блокирует запросы к другим.
- Device пайплайна резолвится один раз при создании:
  `device_map.get(model_id, default_device)`; ключ кеша остаётся `(model_id, kind)`.
- Preload: на старте перечисленные модели создаются заранее — обычные записи LRU,
  без пина. Дефолт `max_pipelines = max(2, len(preload))`; явно заданный лимит
  меньше числа preload-моделей — ошибка конфигурации на старте, не тихое вытеснение.

## Реализация LLM chat

1. Промпт: `pipe.get_tokenizer().apply_chat_template(messages, add_generation_prompt=True)` —
   шаблон чата из самой модели; текстовые части склеиваются, роли проходят как есть.
2. `GenerationConfig`: `max_tokens`/`max_completion_tokens` → `max_new_tokens`
   (дефолт 512, если клиент не задал); `temperature > 0` → `do_sample=True` +
   `temperature`/`top_p`; `temperature == 0` **или не задана** → greedy.
   Сознательное отступление от дефолта OpenAI (`temperature=1`): локальному
   инференсу детерминированный дефолт полезнее.
3. `finish_reason`: `"length"`, если сгенерировано ровно `max_new_tokens`, иначе
   `"stop"`; usage — из perf-метрик og.
4. VLM-запрос (image-части) и `OVINFER_USE_CONTINUOUS_BATCHING=1` — по-прежнему 501.

**Стриминг — мост callback → generator**: og зовёт streamer-callback (push),
HTTP-стриму нужен итератор (pull). Генерация уходит в отдельный поток, callback
кладёт дельты в `queue.Queue`, генератор читает и yield'ит. Детали:

- **Отмена**: клиент закрыл SSE → Starlette закрывает генератор → `GeneratorExit` →
  callback возвращает `StreamingStatus.STOP` → og прерывает генерацию, устройство
  освобождается, лок снимается. Без этого — утечка: NPU молотит до конца под локом.
- Исключение в потоке генерации пробрасывается в генератор через ту же очередь.

## Реализация embeddings

- `TextEmbeddingPipeline` из og; kind `embedding` в ключе кеша — embeddings-модель
  живёт рядом с LLM независимо, со своим device из маппинга.
- OpenAI `input`: строка или список строк → `embed_documents(texts)`; векторы
  в порядке входа.
- `encoding_format`: `float` и `base64` — оба (openai-python по умолчанию просит
  base64; поддержка тривиальна — `struct.pack` + `base64`).
- `usage.prompt_tokens` — best-effort: счёт токенизатором модели, если og
  экспонирует его для этого пайплайна; иначе 0.

## Транспорт (`ovinfer/server.py`)

Порт перенесённого каркаса с тремя изменениями:

- роуты — **`def` вместо `async def`**: FastAPI выполняет sync-роуты в threadpool,
  блокирующая генерация не замораживает event loop (`/health` отвечает во время
  инференса); sync-SSE-генератор Starlette итерирует через `iterate_in_threadpool`;
- chat-роуты зовут `Backend` и собирают OpenAI-тела: `chat.completion` из
  `ChatResult` (id, created, usage); SSE-чанки `chat.completion.chunk`:
  роль → дельты → finish_reason → `data: [DONE]`; `/v1/embeddings` зовёт
  `Backend.embed` и собирает `list`-ответ (`data[].embedding`, usage);
- иерархия `APIError` уходит из транспорта; вместо неё таблица маппинга доменных
  ошибок: `ModelNotFound → 404 model_not_found`,
  `PipelineNotImplemented → 501 pipeline_not_implemented` (формат ошибок OpenAI —
  транспортная деталь).

Pydantic-схемы OpenAI-контракта (`extra="allow"`), маппинг пайплайнов на эндпоинты,
multipart-роуты — без изменений из перенесённой спеки `2026-06-06-openai-server-design.md`.

## Приёмка

Ручные проверки (pytest-инфраструктура — вне v0.1):

1. Контракт не сломан: curl-проверки каркаса (404/422/501 для нереализованных,
   SSE-ошибка, multipart) дают прежние ответы.
2. На этой машине `openvino-env ovinfer server` с `--device-map`, разводящим LLM и
   embeddings-модель по устройствам: реальные chat- (stream и non-stream) и
   embeddings-запросы через openai-python; `OVINFER_MODELS_ROOT=~/.openvino/models`
   переиспользует уже скачанные модели.
3. `--preload` греет модели на старте: первый запрос к прогретой модели не ждёт
   компиляции.
4. `/health` отвечает во время длинной генерации (event loop жив).

PyPI; реальные пайплайны кроме LLM chat и embeddings; ContinuousBatching и VLM;
systemd-юнит;
